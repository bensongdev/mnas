# 기능 검증 템플릿

새 기능을 만들기 전에 이 파일을 복사해 채웁니다. AI 에이전트는 이 내용을 기준으로 구현하고 검증하며, 사람은 마지막 "검토 판정"을 보고 승인합니다.

## 사용자 이야기
나는 (어떤 사용자)로서, (무엇을) 하고 싶다. 그래야 (어떤 이득)을 얻을 수 있다.

예: 나는 앱 사용자로서, 숫자를 1 내리고 싶다. 그래야 잘못 올린 숫자를 되돌릴 수 있다.

## 수용 기준 (눈으로 확인할 수 있게)
- [ ] ...
- [ ] ...

예: "Decrement 버튼을 누르면 숫자가 1 줄어든다", "숫자가 0일 때 눌러도 0보다 작아지지 않는다"

## 위험 요소
- 사용자 데이터 손실? 권한? 결제? 비밀 정보? 데이터 마이그레이션? 접근성?

## 테스트 계획
| 동작 | 테스트 방법 | 증거 |
|---|---|---|
| 초기 상태 | UI assertion | `01-initial-launch` 스크린샷 |
| 상호작용 | UI assertion | `02-before-<동작>` / `03-after-<동작>` 스크린샷 |
| 상태 유지 | 단위/통합 테스트 + 앱 재실행 | 테스트 로그와 스크린샷 |
| 오류 상황 | 별도 테스트 | 오류 화면 스크린샷 |

## 검토 판정
- [ ] 빌드와 테스트 PASS (`verification.md`의 전체 결과)
- [ ] 스크린샷을 직접 열어 확인함
- [ ] 기능에 대한 주장이 assertion으로 뒷받침됨
- [ ] 해당되는 경우 접근성/키보드 조작 확인
- [ ] 알려진 한계를 문서화함
- [ ] 사람이 승인함
